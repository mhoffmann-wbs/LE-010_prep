## Big idea

Linux is not only a system for experts. A huge amount of everyday software is **open source**: anyone can read its source code, and it is usually free to use. This lesson is a tour. You don't have to install or operate any of these programs for the exam. You must recognise each name and know **what it is for**.

Where does the software come from? On Linux you rarely download an installer from a website. You use a **package manager** that fetches a **package** (the program plus information about what else it needs) from a **repository** (an online store of packages run by your distribution). One command installs, updates and removes software.

You can ask the Debian system in this app's terminal which package a file came from:

```bash
dpkg -S /bin/ls
```

```output
coreutils: /bin/ls
```

The program `ls` is shipped in the package `coreutils`.

### Web applications

A **web application** runs on a server, and you use it in your browser. Nothing is installed on your computer.

| Program | What it is for |
|---|---|
| **Kodi** | Media center for your TV: video, music, photos |
| **Jitsi** | Video meetings in the browser |
| **BigBlueButton** | Web conferencing built for virtual classrooms |
| **Moodle** | Learning platform: courses, quizzes, grades |
| **GitLab** | Hosts Git repositories and adds issue tracking and build pipelines |
| **Forgejo**, **Gitea** | Light, self-hosted Git forges, similar in idea to GitLab |

**Git** itself is not a web application. It is the command line tool that tracks changes to source code. GitLab, Forgejo and Gitea are web services built around Git repositories.

</ExamOnly>

### Server applications

A **server application** runs in the background and answers requests from other computers.

| Program | What it is for |
|---|---|
| **Apache HTTPD**, **NGINX** | Web servers: they deliver web pages. NGINX is also often used as a reverse proxy in front of other programs. |
| **MariaDB**, **MySQL**, **PostgreSQL** | Database servers: they store structured data and answer queries. MariaDB started as a fork of MySQL. |
| **NFS** | Network File System: share directories between Unix and Linux machines |
| **Nextcloud**, **ownCloud** | Your own file sync and sharing "cloud" (like Dropbox), with calendars and contacts |
| **Samba** | Shares files and printers with Windows computers, using their protocols |

Web servers are often combined with a database and a programming language to run a site. A well-known stack is **LAMP**: Linux, Apache, MariaDB or MySQL, and PHP.

### Programming languages

| Language | Typical use |
|---|---|
| **C** | Operating systems, drivers, fast programs. Linux itself is mostly written in C. |
| **C++** | Large programs where speed matters: games, browsers, engines |
| **Java** | Business applications; runs on the Java virtual machine; Android apps |
| **JavaScript** | The language of web browsers, and of servers through Node.js |
| **Python** | General purpose; popular for scripts, automation, data science |
| **PHP** | Server-side web pages (for example WordPress and Moodle) |
| **Rust** | Systems programming with strong memory safety. Used more and more near the kernel. |
| **Go** | Fast, simple language for network services and tools; created at Google |

Two groups matter. **Compiled** languages (C, C++, Rust, Go) are translated into a machine-code program before running. **Interpreted** languages (Python, PHP, JavaScript, and shell scripts) are run by another program, the interpreter, that reads the source directly. Java sits between: it is compiled to bytecode that a virtual machine runs.

### Software packages and repositories

A **package** is one file that holds a program, its data files and metadata: name, version, and its **dependencies** (other packages it needs). A **repository** is a server that holds many packages, with an index that the package manager downloads. Your distribution runs official repositories; each package is signed so that your system can check where it came from.

The point of this is that the package manager can resolve **dependencies** for you: asking for one program also brings the libraries it needs. It can also update everything with one command, and remove a program cleanly.

You can see which tools this guest has. It is Debian, so it has the Debian tools and not the others:

```bash
for t in dpkg rpm; do command -v $t || echo "no $t"; done
```

```output
/usr/bin/dpkg
no rpm
```

### Package management tools

Two layers exist. The **low-level** tool installs, removes or inspects one package file and doesn't fetch anything. The **high-level** tool talks to the repositories, downloads what is needed and resolves dependencies, using the low-level tool underneath.

| Family | Package file | Low-level tool | High-level tool |
|---|---|---|---|
| Debian-based | `.deb` | `dpkg` | `apt`, `apt-get` |
| Enterprise Linux (Red Hat family) | `.rpm` | `rpm` | `dnf` |
| SUSE-based | `.rpm` | `rpm` | `zypper` |
| Alpine | `.apk` | | `apk` |

`apt` is the friendlier, newer front end that is meant for people at the keyboard. `apt-get` is the older one with a very stable interface, and scripts often use it. Examples (shown, not run here, because installing needs administrator rights and the network):

```bash static
sudo apt update              # refresh the list of packages in the repositories
sudo apt install gimp        # install GIMP and the packages it needs
sudo apt remove gimp         # remove it again
dpkg -l                      # list installed packages
sudo dnf install gimp        # the same on Fedora, RHEL, AlmaLinux, Rocky
sudo zypper install gimp     # the same on openSUSE and SUSE
sudo apk add gimp            # the same on Alpine, as root
```

`rpm` and `dpkg` can install a single downloaded file, but they do not fetch dependencies, which is why you normally use `apt`, `dnf` or `zypper`.

</ExamOnly>

## Exam traps

<Callout title="Match the tool to the family">
  <p>`dpkg` and `apt` (or `apt-get`) work with `.deb` packages on Debian and Ubuntu. `rpm` and `dnf` handle `.rpm` packages on the Red Hat family, `rpm` and `zypper` on SUSE, and `apk` is Alpine's own tool. A question that shows `dnf install` is not about Debian.</p>
</Callout>

<Callout title="Low-level or high-level">
  <p>`dpkg` and `rpm` work on package files you already have and don't fetch dependencies. `apt`, `dnf`, `zypper` and `apk` use repositories and resolve dependencies.</p>
</Callout>

<Callout title="Chromium is not Chrome, and Git is not GitHub">
  <p>Chromium is the open source browser, and Chrome is Google's product built on it. Git is the version control tool, while GitLab, Forgejo and Gitea host Git repositories on a server.</p>
</Callout>

<Callout title="Web server or database">
  <p>Apache HTTPD and NGINX are web servers. MariaDB, MySQL and PostgreSQL are databases. Samba talks to Windows, NFS to Unix and Linux. Nextcloud and ownCloud are for file sync and sharing.</p>
</Callout>

<Callout title="Raster or vector">
  <p>GIMP edits pixel images (raster). Inkscape draws vector graphics. GPG is for encryption and signing, and R is for statistics.</p>
</Callout>
